# Contract C RC1 Open Questions

- Can one stable CAL semantic package serve materially different policies without consumers reopening raw evidence?
- Which current CAL fields are semantic state versus replay/debug telemetry?
- Is report-only transport ever sufficient for machine consumers?
- Is the existing Gate primitive enough for diverse policies?
- Does `promote | hold | reject` belong in the generic runtime or only one policy family?
- Are receipts individually content-addressed or only integrity-covered by the package root?
- Is a reference-oriented C package sufficient, or is a portable text snapshot required?
- Which unknown reasons actually change downstream behavior?

These are research questions, not unresolved defects in locked Contract B.
